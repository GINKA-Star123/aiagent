# V1.2 第五至第十批修订方案

修订日期：2026-10-22。性质：待逐批实施、验收的规划，不是完成报告。

主计划：[V1.2 十批次实施目标](v1.2-ten-batch-implementation-plan.md)。本次只更新规划文档，不修改业务、配置、测试、第四批交付文档或外部分析报告。

## 一、结论与进度口径

**V1.2 后半程建议从“分别优化模块”转向“让现有 Agent 有可信的执行与交付纪律”：先修批准载荷和所有权，再统一操作的准入、失效与提交，随后完善后端输出/主动行为，用一个有限 Rust 组件强化 Prompt Injection 信任边界，最后收敛故障、数据、性能和发布证据。**

这不是把 V1.2 改成纯安全版本。后三条非安全主线仍然明确保留：运行一致性与预算、Voice/Presence 后端体验协议、性能成本与故障恢复。安全约束是这些能力的前提，不用新增 Agent 数量衡量版本进步。

“第五至第十批”实际是六批，继续保持全版本十批总数，不新增第十一批。用户所称“后五批次”在本次按明确编号范围 5—10 处理，不擅自删除其中一批。

## 二、参考材料与取舍依据

已阅读外部报告 `F:/REA/celestial-reverie-analysis/celestial-reverie-final-conclusions.md`。报告日期为 2026-10-20，对目标游戏的客户端发现有明确证据边界，对 aiagent 的问题属于当日静态审查；本次重新核对相关项目源码，没有运行游戏、外部后端、Provider、测试或故障复现。

从报告吸收的内容：

1. 保留 Python/LangGraph 与现有 State、Planner、RAG、Memory、Vision，不重造多 Agent 框架。
2. 把“谁的哪次意图，当前仍允许提交哪些副作用”作为核心操作契约。
3. 取消首先撤销后续提交资格，不承诺供应商立刻停止计算。
4. 长期事实、短期观察、Prompt 上下文、聊天记录与输出投递记录分开管理。
5. 区分生成完成、资源就绪、交付、消费和播放；先用模拟消费者验证后端。
6. 主动行为先准入，再生成；用户回合优先、共享冷却、队列有界、过期事件不补发。

不照搬的内容：

- 游戏内部模型、RAG、Memory 和服务端架构仍未知，不以客户端类名作为本项目技术选型证据。
- 不复制游戏资源、私有协议、固定端口、冷却参数或全局单例。
- 不开发前端、摄像头持续采集、屏幕监控、全新 WebSocket 平台或复杂身体动作系统。
- 报告推荐 Rust 媒体解析隔离；用户本次明确希望 Prompt Injection 成为 Rust 安全方向。因此本版选择**一个 Rust 上下文审查与用途策略组件**，媒体隔离列为另一个候选及残余风险，不同时建设两个 Rust 边界。

选择 Prompt Injection 方向的理由是当前已有多个真实文本汇入口，且会影响规划、回答和记忆；选择有限确定性策略而非“语义安全大脑”的理由是前者可做跨语言 Contract、资源限制与故障测试。若 ADR 无法证明 Rust 带来的审计/部署边界收益，必须提交范围变更审阅，而非为了语言目标堆一个无集成 demo。

## 五、第五批：安全落库、可信身份与执行边界修复

### 5.1 明确交付

1. **批准载荷直接落库。** 自动长期记忆只接收服务端批准的事实集合和受控 metadata，不把原始问答再次交给 Mem0 自由抽取。核实当前 Mem0 的无二次推断写入接口、图存储行为和返回结构；不支持受控写入的路径先禁用，不靠 Prompt 中“只围绕已审核提示”保证安全。
2. **所有写入口共用边界。** 自动记忆、视觉 hint、用户编辑/合并、异步重试分别定义来源与授权，编辑正文仍过滤；策略字段、原始用户名和 metadata 不得成为秘密内容旁路。业务失败不得记录为 stored。
3. **可信调用者。** 采用成熟 Bearer 验证适配器；若部署无身份服务，先采用服务端维护的高熵 token 与固定 principal 映射，且不承担注册/刷新/账户平台。生产禁止信任任意 `user_id`/Header；local-dev 使用显式固定测试主体，不能自动迁移为云默认。
4. **资源归属。** 制定并落实 session/thread/call/memory/image/audio/output/task 的用户面所有权矩阵；管理接口继续走 admin 授权，不借管理凭证替普通用户自报身份。下载、查询、打断、删除同样校验，不能只检查创建。
5. **显式故障。** 真实生成失败返回有稳定错误码的 degraded/error，默认不语音播报、不长期记忆、不把用户原文追加为有效助手历史；Mock 仍可用于离线测试，但 metadata 标明 Mock。不要把修改 strict 评测接口当作普通链路已修复。
6. **小范围契约修复。** URL 空值单独处理，结构解析后仅接受批准 scheme/host/站内路径，拒绝协议相对地址、userinfo 和越界路径；本地文件按规范化路径与对象归属检查。Presence 复用现有 payload builder/normalizer。
7. **冻结最小威胁模型。** 身份/受控副作用与 Prompt Injection 信任边界为两条安全主题；记录媒体解析和其余候选的处置，不扩张为四个并行安全项目。

### 5.2 涉及位置

`aiagent/graphs/memory_graph.py`、`aiagent/memory/{memory_intake,mem0_memory,null_memory}.py`、`aiagent/graphs/llm_graph.py`、`aiagent/services/llm_service.py`、`apps/api/routes/` 的受保护入口、`apps/core/runtime.py`、Live2D payload 与 Presence mapper。认证适配器位置按现有 API 边界新增薄模块，不进入 Graph 实现登录。

### 5.3 测试与验收

- 正例：批准的普通偏好可写一次，编辑/合并正常，同用户查询和下载成立。
- 对照：原始问答含 canary Secret，而批准事实只有无敏感偏好；直接捕获真实适配器发给 Mem0 的请求，Secret 在 messages/metadata/日志/待重试载荷均不得出现。
- 负例：guard 异常、计划缺失、计划正文被改、用户伪造身份、跨用户 call/音频/Memory、未授权全局控制均零受控副作用。
- 故障：真实 Provider 模拟 401/超时/空输出，不能返回“原文=model 成功”；正常 Mock 与真实成功路径分别验证。
- 文档产物：`docs/security/threat-model-v1.2.md`、身份/资源矩阵、Memory 批准载荷契约、配置迁移与回滚说明，均为后续待创建文件。

本批完成不表示并发删除已完全解决；异步撤销与原子提交属于第六批，真实重启恢复属于第九批。

## 六、第六批：操作生命周期、原子准入与提交一致性

### 6.1 最小操作契约

复用已有标识，不另造五套互不关联的 ID：

| 字段 | 语义 |
| --- | --- |
| principal / session_id / call_id | 已验证归属；认证会话、聊天会话、语音通话不混为一个概念 |
| operation_id / payload_digest | 业务幂等身份与载荷摘要；request_id 只是每次传输/日志关联 |
| turn_id / generation / fence | 当前回合、代际与提交资格；返回 token 必须传到提交点 |
| deadline / retry budget | 服务端授予的整轮时间和调用预算，非客户端任意延长 |
| persona/config/policy version | 最小不可变引用/摘要，不能把全部配置或 Secret 复制进记录 |
| cancellation / memory revocation version | 操作撤销与长期记忆禁用/删除屏障，按作用域定义 |

状态至少区分 `accepted/running/completed/failed/cancelled/unknown`。同键同载荷复用，异载荷冲突；幂等保留窗口结束后的行为明确，不宣称永久去重。

### 6.2 原子与执行边界

- 在现有 RedisStateStore/本地适配器上加薄的操作仓储：所有权、幂等占位、准入与 generation 推进在同一原子边界内完成。Redis Cluster 多 key 使用同作用域 hash tag，不能写无法同槽执行的 Lua。
- call 准入与 next_turn 合并；取消、结束、换代和输出提交比较预期代际。普通 Python 锁不代表多进程原子性。
- 云端共享时间/租约以服务端可信时间为准；进程内剩余预算用 monotonic，不能直接比较两台机器的 monotonic 数值，也不接受客户端时钟推进安全状态。
- 审查 Graph 的隐式 checkpoint 写入和摘要更新：官方 saver 可复用，但其存在不证明过期操作不能写入。用适配器校验或隔离 generation 命名空间及可见指针，拒绝旧结果进入当前上下文。
- 先枚举提交点，再逐项贯通：会话/短期摘要、Memory、输出注册、TTS/本机播放、Live2D 命令及可下载对象。只在 Runtime 入口做一次检查不合格。
- 同步线程超时仍可能继续运行；撤销后不能推进当前可见状态。已发出的 Provider 请求、已开始的物理播放和已外发数据只能记录与止后续行为，不能承诺撤回。

### 6.3 Memory 删除的现实边界

Redis 与 Mem0/Qdrant/Neo4j 没有天然跨库事务。不能用“查一次撤销标记再写”宣布没有竞争窗口。需要在实施 ADR 中选择并验证以下组合：

1. 受控写入 intent 带不可变批准载荷、幂等键与撤销版本。
2. 用户/agent 清空后提升记忆数据 epoch，旧版本迟到写入不再可检索、注入或恢复为当前记忆，并安排物理清理。
3. 单条删除的 tombstone/记录修订与“全部清空的 epoch”区分，不能删除一条就误隐藏其余有效记忆；单条与分层细则在第九批完成。
4. 禁用长期记忆时撤销旧写入资格，重新启用不能恢复此前排队任务；禁用本身不冒充清空已有数据。
5. 底层图/向量后端必须证明版本与归属隔离可执行；无法保证的写入/图检索路径先关闭或受限，不以 UI 不展示代替隔离。

逻辑不可见与物理删除分别报告。旧版本隔离产物也必须有 TTL/清理责任，不能无限保留。

### 6.4 整轮预算与性能起点

覆盖 State、Planner、LLM、摘要、Memory policy、Vision、ASR/TTS 与 SDK 隐式重试。先明确哪层负责重试，避免 SDK 与业务循环相乘；重试前校验剩余时间与撤销状态，429 退避不得越过总 deadline。401 等永久错误不应自动重试。

本批先采未改动路径的基线，再加入一致性控制后采样，记录环境、负载、冷/热、样本数、真实/Mock；第九批做热点优化与综合对照。不得把预算取消请求变多包装为延迟改善。

### 6.5 测试与产物

- 本地与 Redis 相同 Contract；真实 Redis 两进程抢同一 operation，不同用户不共用结果。
- 旧 fence、租约过期、新回合、打断/结束后旧 LLM/TTS/Memory/checkpoint 延迟返回；旧资格不得推进当前可见结果。
- 删除/禁用完成与后台任务完成交错；API 返回撤销成功后不得再出现可见旧事实。
- 共享状态断开时明确失败，不静默切本地；外部响应丢失标记 unknown，spy 记录实际调用数。
- 产物：操作状态机与提交点清单、Redis key/TTL/迁移说明、预算表、可重复性能采集入口、并发/故障报告。拟新增模块优先位于 `aiagent/state/`，不建立第二 Runtime。

## 七、第七批：后端输出交付、观察与受控主动性

### 7.1 输出契约

沿用 ResponsePacket 作兼容聚合结果，增加强类型 segment 与事件，至少绑定 schema_version、operation、output、segment_index、event_id、sequence 和结构化 payload。

生成状态、资源状态、消费状态是三个维度：

```text
生成：accepted -> running -> completed / failed / cancelled
资源：text_ready / audio_ready / timing_ready
消费：delivered -> playback_started -> playback_finished / failed
```

纯文本不需要播放回执；audio_ready 不等于 speaking。客户端 playback_finished 是“客户端报告完成”，不是服务端证明用户已经听到。

通过显式版本接口增加分段查询、最小快照与回执，继续保留旧聚合字段。不强制新增 WebSocket，不承诺 token 级流式；允许已有 TTS 整段完成后发布事件，真实增量 Provider 能力以后再扩展。

恢复需定义快照的高水位 sequence：先取得一致快照及水位，再取之后事件；游标过期明确重置，不只用可变列表下标。事件/分段队列有条数、字节、保留期和缺段等待上限。

### 7.2 会话资源与主动准入

- Speaking/Streaming/Interrupt 按用户会话隔离，persona 为会话/操作快照；全局切换只保留在明确授权管理模式。
- 物理音频设备保持单独互斥与抢占策略；跨用户请求不能通过全局 interrupt 任意打断另一个用户。
- Presence 不再独立决定“现在能说”：共享第六批准入，用户显式回合优先，服务端冷却、用户可关闭、同类事件合并、过期丢弃。
- 当前开场可继续使用规则生成，不为本批新增持续后台主动 LLM。先用并发 session/open 与合成事件验收。
- 观察信封保留 source、observed_at/received_at、expires_at、类别、分数含义、允许用途和 operation；过期观察不能注入 Prompt，允许 Prompt 不等于允许写 Memory。
- 人脸/角色候选置信度不是身份认证，文字观察和模型产生的 reasoning 均不是用户授权。

### 7.3 测试与产物

模拟消费者覆盖音频先到、文字先到、重复、缺段、乱序、背压、快照期间并发事件、重连和游标过期；未授权、旧 generation 与重复 ACK 不得推进状态。

冻结时钟并发 open 只批准一次开场；禁用、用户正在处理、观察已过期、事件超预算均无新主动副作用。原聊天/Voice 聚合 Contract 继续通过。

产物：分段/回执/快照/观察契约、兼容矩阵、模拟消费者、Presence 准入规则与测试报告。复用 `aiagent/expression/`、`aiagent/perception/`、`aiagent/presence/` 和 `aiagent/schemas/`，不重写播放器或前端。

## 八、第八批：Prompt Injection 防护与 Rust 审查组件

### 8.1 安全目标与威胁模型

目标：**攻击者控制用户正文、检索文档、记忆、摘要或视觉/OCR 文本时，不能因此改写系统授权、资源归属、操作资格，或使未批准内容通过真实写入/执行点。**

另行评估“模型是否跟随恶意内容生成错误回答”。这是概率性语义问题，不与确定性权限控制混成一个“安全分数”。即使检测未命中，硬权限与提交控制仍必须成立。

假设 Python 主服务、部署配置和固定策略是可信计算基。Rust 子进程不提供对恶意 Python 主进程的防护；如果主进程能自行绕过调用，它就不是对主进程的外部强制网关。验收必须枚举所有生产调用点并测试正常运行链路无旁路，不能用 mock 一个 Rust 函数宣称已经隔离。

### 8.2 两层控制，不做“Rust 安全大脑”

| 层 | 确定承担 | 明确不承担 |
| --- | --- | --- |
| Rust ContextGuard | 严格 schema、来源/用途策略、边界资源限制、可解释风险信号与裁决 | 用户认证、跨库事务、通用语义理解、猜测文本真伪 |
| Python 适配与执行点 | 服务端装配可信信封、校验裁决与内容摘要、当前 owner/generation、批准载荷和能力检查 | 把 risk_score 当身份凭据、把模型建议当授权 |

拟采用单个 `security/context-guard/` crate 与 Python 薄适配器，以有界 CLI/stdio 通信。路径为规划建议，实施前按仓库治理确认；本次未创建 crate。

输入 ContextBlock 至少区分来源、可信度、用途、归属作用域、内容摘要、TTL 和 policy version。可信元数据来自经过验证的服务端调用上下文；正文里的 `role=system`、伪造“管理员确认”、JSON 字符串、Markdown 标签不改变 envelope 权限。Rust 只能验证传入可信信封与固定策略的一致性，不能自行证明外部身份。

### 8.3 确定性策略

1. 可信系统规则与经部署审阅的 Persona 配置和不可信数据分离；用户可编辑/导入的 Persona 文本不能自动升级为系统策略。
2. RAG/Memory/OCR/观察默认仅供事实参考，不能声明工具授权、文件路径、网络目的地、会话主体或 policy override；`allow` 也不把正文变成高优先级指令。
3. 摘要与模型规划保留来源污点，不得经过总结就洗成可信；State/Planner 的 `reply_instruction` 与 Memory policy 输出仍是有限提案。
4. 长期记忆只接受第五批批准事实与适用授权。直接“记住这段恶意指令”和通过 RAG 诱导的“替用户批准记忆”必须区分；自然语言自称获得确认不构成可信确认。
5. 分隔符、引用包装与高风险指令模式只作为纵深防御/风险信号，不承诺完整识别跨语言、隐写或混淆注入。命中可隔离块，不通过自动改写声称已消毒。
6. 模型输出中的动作、URL 与能力建议必须经过已有结构和权限许可，不能执行任意命令或访问任意网络；本批不新增 shell/浏览器工具以展示安全效果。

### 8.4 协议、资源与故障要求

- 版本化、严格字段、重复 key/未知枚举/深度与总输入上限；输出大小、块数量、耗时、并发和缓冲均有界。
- 固定可信 executable 与策略路径，禁止请求指定程序、任意文件或网络；默认不用 unsafe，不使用 shell 拼接调用，成熟库实现解析/摘要。
- 子进程最小环境，不继承整个 `.env`、Provider key 或 Redis 凭据；stdout 仅协议，stderr 不直接回传，内容摘要也按敏感元数据管理。
- 裁决绑定输入摘要、操作与策略版本，父进程核验后再用；进程返回的陈旧 allow 不能绕过新取消/撤销状态。
- panic、进程退出、timeout、缺二进制、版本错误、截断/超量输出均按 failure；父进程可终止并回收子进程，不用“等待超时”冒充进程已退出。
- 审查失败时丢弃依赖该裁决的不可信上下文、禁止相关写入，并显式 degraded；若该上下文是完成请求必需条件则返回错误。不得自动切到未经审查的原文路径。
- 独立子进程不是完整 OS 沙箱；文本审查组件不因此宣称隔离了图片解码、网络和文件权限。Windows 本地与 Linux 容器行为分别有集成测试。

### 8.5 数据与验收

建立独立版本化攻击/正常集，建议最小 40 条攻击加 20 条正常对照，覆盖直接/间接指令、角色伪造、知识库注入、记忆投毒、摘要洗白、OCR/Vision 指令、伪造确认、Secret 诱导、跨用户引用、编码与格式边界。样例规模是交付下限，不是统计置信度或安全充分性保证。

正常集包含“讨论 Prompt Injection 的教程”“引用恶意语句做分析”“正常记忆偏好”和多语言资料，检查误拒绝；不以见到 ignore/system 等词就全部拦截获得高分。

验收分三份证据：

- Rust 单元/边界/fuzz 与协议 Contract：确定性场景全通过，资源失败不绕行。
- Python 整链副作用测试：在实际 Memory/状态/输出适配点用 spy/canary 证明无越权、无未经批准写入、无旧代际提交；不以“检测器返回 block”代替实际效果。
- 真实 Provider 攻击评测：固定模型/样本/策略版本，分别记录攻击成功率、误拒绝、答案失真、Secret canary 外泄、上下文被隔离比例及误报。Mock 只能证明协议，不能代表这项通过；已知绕过必须保留，不能通过删样本美化报告。

真实模型如仍有语义绕过，公开残余风险；涉及硬权限/真实 Secret/未经批准副作用的失败阻止发布，不能平均到正常样本分数中。Secret canary 是合成标记，真实凭据原则上不进入 Prompt，不靠输出过滤保护已发出的密钥。

### 8.6 媒体隔离决策

外部报告的受限媒体 worker 确有可验收价值，但与文本注入审查是不同目标。本版不同时实现两个 Rust 组件。图片解析继续进程内的残余风险需在第五批登记、第十批按实际公网暴露决定：限制/禁用未受控入口、使用已验证的既有隔离部署，或经审阅调整版本范围。不可接受的媒体拒绝服务风险不能仅写“下版再做”就获得上线许可。

文档产物：Prompt Injection 威胁模型补充、Rust 选型 ADR、ContextBlock/GuardDecision 协议、策略表、攻击集说明、故障矩阵与部署/回滚指令，均待实施时创建。

## 九、第九批：故障恢复、数据生命周期与性能成本收敛

### 9.1 复用现有任务系统

继续使用 CloudTaskQueue，不新建 Memory 专用分布式队列。补占位、记录与入队原子性、owner/operation 绑定、worker claim/租约与结果提交资格。unique_key 不是载荷校验，更不是持久幂等的全部。

Memory 后台任务只携带批准载荷与最小版本引用；显式本地开发模式可用非持久适配器，但云模式不因 Redis 故障落回线程池。可选记忆失败可以明确失败且不阻塞已批准的聊天结果，不能伪装成功。进程重启后不能把“之前函数被排队”当作记忆已写入。

对外部执行未知且后端不支持幂等的任务，使用稳定记录 ID、可查询结果或进入人工核对；不要盲目自动重放。死信重放需再次验证 owner、deadline、删除/撤销版本与批准策略，管理员也不能无条件复活旧载荷。

### 9.2 生命周期

| 数据 | 必须明确 |
| --- | --- |
| Memory 与图/向量派生项 | 单条/分层/全部删除、版本隔离、物理清理、读取范围 |
| 聊天与摘要/checkpoint | 删除范围、来源失效、当前可见指针、旧命名空间 TTL |
| 图片/音频/输出对象 | owner、过期、下载 URL 有效期、孤儿对象与失败临时文件清理 |
| operation/task/call/事件 | 状态保留、幂等窗口、快照/游标过期、死信内容最小化 |
| 审计/日志/质量报告 | 脱敏、保留期、原始答案默认关闭与访问范围 |
| 备份/恢复 | 删除标记的独立保留、备份淘汰周期、恢复后重新应用 tombstone，不声称即时物理抹除 |

清理必须可重复且有界，不能在查询时无限 scan；并发写入与分页清理有游标/水位规则。对单条删除不能承诺自动清除所有历史对话中的同义事实，范围必须明确给用户和运维。

### 9.3 故障与性能

真实 Redis 双进程、Worker 中途退出、对象存储 5xx、SDK/Provider 401/429/503/超时/响应丢失、重试退避中取消、队列重复与满载，均复用第六批状态机验证。不重复建设断路器、readiness 或 metrics，只补现有控制遗漏。

性能报告至少包含环境、提交/配置/fixture 摘要、样本数与并发、冷启动/稳态、P50/P95、错误/取消/降级率、队列等待/峰值、CPU/RSS、阶段调用数与预算用尽。已支持增量阶段可报告首段时延；没有真实增量的路径明确 unavailable，不伪造首 token 指标。

同环境对照一项真实热点优化，例如消除重复初始化/检索、降低可选 IO 阻塞或限制无意义排队，具体选哪一项由基线决定。缓存仅在身份、人格、模型/策略/数据版本和失效语义明确时采用；第四批质量、第五批安全、第六批一致性、第八批注入边界不得退化。

Token 仅采用 Provider usage；缺失则 unavailable。费用需要供应商价格版本与币种，否则只报调用数/音频秒数等代理指标；不预填“降低 30%”。若没有值得做的热点，接受有数据、经审阅的不优化结论，不能用空报告替代分析。

交付：可靠性/数据 runbook、恢复/重放限制、故障报告、TTL/删除矩阵、性能成本与容量报告、优化 diff 或明确不优化决定。真实集成不进入普通离线每次提交时，必须提供独立 CI/手动门禁与发布证据入口。
