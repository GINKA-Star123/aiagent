# V1.2 十批次实施目标

## 一、文档定位

本文将 V1.2 后端优化收敛为十个可独立验收的批次。2026-10-22 根据当前源码、用户进度和 `F:/REA/celestial-reverie-analysis/celestial-reverie-final-conclusions.md` 修订第五至第十批；详细理由、源码核对、测试矩阵与边界见 [第五至第十批修订方案](v1.2-batches-05-10-revised-roadmap.md)。旧版引用的 `docs/next-stage-optimization-roadmap.md` 当前不在仓库内，不将其视作仍可访问的实施入口。

**状态口径：前三批按用户反馈已实施；第三批曾反馈五个用例与两个容器导入验证通过，本次没有重跑。第四批完整代码已交付，但用户明确尚未编写，不能标记为已实现、已接入 CI 或已验收。本文不修改第四批交付文档，也不将其计划能力当作现有运行能力。**

本次“第五至第十批”是六个批次，保持全版本十批总数，不新增第十一批。下列第一至第四批保留原目标，后六批采用本次修订目标。

V1.2 的定位是：

```text
Agent 质量、安全治理与后端工程化阶段
```

安全是 V1.2 的重要方向之一，但不是全部。V1.2 同时覆盖 Agent 质量、Runtime/Graph 性能与成本、多 Worker 执行状态一致性、Cloud/Worker 可靠性、数据生命周期和工程交付。

本版本明确不包含：

- Flutter、Qt、Web 控制台或其它前端分支。
- 前端 API model、页面、交互、Live2D 舞台或语音 UI 改造。
- 将整个 Python API、RAG、Memory、Voice 或 Runtime 重写为 Rust。
- 在威胁模型完成前预设必须开发某一种 Rust 安全工具。
- 新增复杂多 Agent 架构、第二套 RAG/Memory 或没有质量基线的新 Provider。

## 三、共同执行规则

十个批次统一遵守以下规则：

1. 每批只有一个主要可验收结果，不在同一批次混入无关重构。
2. 每批至少包含实现或配置、自动化测试、验证指令、文档影响和回滚说明。
3. 新增 API 行为必须同步 Contract 测试；新增配置必须同步 `.env.example`、云模板和配置文档。
4. Mock smoke 用于证明工程链路可运行，不作为真实模型质量证明。
5. 真实 Provider 评测与离线/Mock 测试分开运行、分开报告。
6. 所有测试数据必须是合成数据、公开数据或经过脱敏的数据，不提交真实用户隐私。
7. 所有性能结论必须记录环境、样本量、请求类型和统计口径。
8. 安全目标由风险评估选择，不以 Rust 代码量作为版本完成条件。
9. 多 Worker 状态分叉属于已存在的功能缺陷，第 2 批不得被取消或推迟到收尾阶段。
10. 前端工作在十批次中始终不进入范围。
11. 第五至第十批优先修执行与提交边界，不用新增 Agent、第二套任务平台或通用 Rust 网关代替问题修复。
12. 外部分析中的缺陷属于静态发现，需在实施时用测试复现；本次规划未执行测试，不声称风险已被修复。

## 第 1 批：V1.2 基线与目标矩阵

### 目标

建立 V1.2 的统一起点，用实际代码、测试和可执行数据确认哪些能力已经完成、哪些是功能缺陷、哪些只是进一步优化空间，并据此冻结十批次范围。

### 主要工作

- 盘点 V1.1 已有的 API Contract、Mock smoke、RAG 评测、Memory/Vision/Voice 测试和 Cloud 运维测试。
- 建立 Agent 质量、性能与成本、执行状态、Cloud 可靠性、安全、数据与工程治理六类现状矩阵。
- 选取少量代表性文本聊天、RAG、Memory、Vision、Voice 请求，记录当前状态、错误和阶段 metadata。
- 盘点所有进程内状态与共享状态，包括 session、LLM thread/checkpointer、persona runtime、Memory、Realtime call、限流、熔断和 metrics。
- 记录生产默认 Worker 数、Python 版本、容器版本、依赖来源和当前测试入口。
- 创建一条可重复运行的基线命令，输出机器可读结果，例如 JSON 报告。
- 明确每个后续批次的目标、非目标、负责人、输入依赖和验收证据。

### 主要交付物

- `docs/v1.2-scope-and-baseline.md`
- V1.2 基线采集脚本及运行说明。
- 机器可读的基线报告结构。
- V1.2 目标矩阵和明确非目标清单。
- 当前功能缺陷与一般优化项的分离清单。

### 完成标准

- 一条命令能够生成基线报告。
- 六类主线均有当前状态、已知缺口和验证方式。
- 多 Worker 状态问题和交付地基问题被明确标记为前置项。
- 后续九批范围可审阅，不存在“先实现再决定目标”的倒置。

### 本批不做

- 不直接开始大规模性能重构。
- 不决定最终 Rust 组件实现。
- 不扩充真实 Provider 或前端能力。

## 第 2 批：多 Worker 执行状态一致性

### 目标

修复生产多 Worker 下会话、LLM 线程、人格缓存和清理操作可能落入不同进程、造成上下文丢失或状态分叉的问题。

### 主要工作

- 为会话、短期对话线程和 LangGraph checkpointer 选择共享存储方案，优先复用 Redis 或项目已有共享基础设施。
- 外置 persona/runtime 与 thread/user/session 的必要映射，避免状态仅保存在 Python 单例或模块级字典中。
- 明确 `user_id`、`session_id`、`thread_id`、`call_id`、`turn_id` 和 `request_id` 的关系。
- 统一跨进程清理语义：会话关闭、用户 Memory 清空、Realtime call 结束和缓存失效应对所有 Worker 生效。
- 为共享状态定义 key 前缀、schema version、TTL、最大大小、序列化格式和升级兼容策略。
- 规定共享存储不可用时各能力的 fail-open/fail-closed 行为，禁止静默回退导致不同 Worker 持有不同会话真相。
- 增加多 Worker Contract/smoke：同一用户连续请求由不同 Worker 处理时，上下文仍保持一致。
- 增加迁移开关和回滚方式，允许在异常时退回明确的单 Worker 模式。

### 主要交付物

- `docs/operations/v1.2-execution-state-and-gates.md` 中的执行状态部分。
- 共享状态 schema 和 key 约定。
- 多 Worker 一致性测试和 smoke 指令。
- 迁移、回滚和共享存储故障说明。

### 完成标准

- 生产默认 Worker 并发下，同一 session 的多轮上下文连续率为 100%。
- 清理或关闭操作在所有 Worker 上生效。
- 状态存储不可用时返回符合约定的错误或降级 metadata，不发生静默分叉。
- 单 Worker Mock 模式仍可稳定运行。

### 本批不做

- 不重写完整 Runtime。
- 不做与执行状态无关的性能缓存。
- 不引入新的前端 session 协议。

## 第 3 批：CI、依赖与容器地基

### 目标

建立后续批次统一使用的自动化门禁，固定依赖与运行时，使 V1.2 的质量、安全和可靠性变化可以重复验证。

### 主要工作

- 建立最小 CI 流水线：静态检查、单元测试、API Contract、Mock smoke、配置一致性和仓库卫生检查。
- 将测试分成每次提交、计划任务和手动真实 Provider 三层，避免重依赖下载阻塞常规门禁。
- 确定 Python 依赖唯一真源，明确 `pyproject.toml`、`requirements.txt`、`requirements-cloud.txt` 与锁文件的关系。
- 增加依赖漂移检查，防止声明文件和锁文件不一致。
- 对齐本地、CI 和生产镜像的 Python 版本，无法对齐时记录理由和兼容测试。
- 生产容器使用非 root 用户，限制可写目录，不包含测试资产、模型缓存、Secret 和不需要的开发工具。
- 固化常用测试入口，避免每个批次自行拼接不同命令。

### 主要交付物

- CI 流水线配置。
- 依赖锁文件和依赖维护说明。
- 容器运行用户、写目录和 Python 版本说明。
- 本地与 CI 的统一验证命令。

### 完成标准

- CI 可从干净环境重复执行，并在失败时定位到具体层级。
- 核心单元测试、API Contract 和 Mock smoke 是合并必过项。
- Python 依赖存在唯一真源和漂移检查。
- 生产镜像以非 root 用户运行。
- 本地、CI、镜像的解释器版本已经对齐或有书面差异结论。

### 本批不做

- 不要求真实大模型评测进入每次提交流水线。
- 不追求一次性接入所有扫描器。
- 不将 CI 扩展成新的运维平台。

## 第 4 批：Agent 质量评测闭环

### 目标

让 RAG、Memory、Vision、Persona 和主聊天的质量变化可以用后端评测发现、定位和比较，而不是只靠人工体验。

### 主要工作

- 扩展 RAG 测试集，覆盖别名、事实问题、无答案、易混淆和低相关检索。
- 同时记录检索级和答案级指标，区分“召回了正确内容”和“最终回答被内容充分支撑”。
- 为 Memory 建立写入、过滤、去重、冲突、置顶、禁用、删除和错误记忆影响回答的回归样例。
- 为 Vision 建立角色图、日常图、文档/截图、非角色图和低置信度样例。
- 为 Persona 和主聊天建立小型行为集，覆盖角色一致性、知识问答、情绪支持、拒答和能力降级。
- 固定评测数据版本、随机性参数、结果结构和失败样例归档方式。
- 将稳定、离线、低成本的评测接入 CI；真实 Provider 评测采用固定命令和独立报告。

### 主要交付物

- `docs/quality/v1.2-agent-evaluation.md`
- 扩展后的评测 fixture。
- 统一质量报告 schema。
- 离线门禁和真实 Provider 评测指令。

### 完成标准

- RAG、Memory、Vision、Persona/主聊天均有可重复评测入口。
- 至少一个检索级指标和一个答案级指标进入常规门禁。
- 评测失败能够归因到检索、策略、上下文、生成或降级环节。
- Mock 通过不会被描述成真实模型质量通过。

### 本批不做

- 不为了提高单一分数引入复杂模型评审平台。
- 不使用真实用户对话作为默认评测集。
- 不开发前端评测页面。

## 第 5 批：安全落库、可信身份与执行边界修复

### 目标

先修复已能从当前源码定位的执行边界问题：审批的内容就是实际持久化的内容，资源访问来自可信主体，生成故障不能伪装成成功回答。

### 主要工作

- 承接第四批唯一 guard 路径；在最终存储点再次拒绝缺失、未批准或已变更的计划，不重复实现第四批测试框架。
- 将 Memory 自动写入从原始问答再抽取改为批准事实载荷；覆盖编辑、合并、视觉 hint、异步任务及相关日志，禁止原始敏感内容绕行。
- 明确用户认证与 admin token 的不同职责；请求中的 `user_id`、`X-User-ID`、call ID 和 CORS 不能作为身份凭证。
- 对 Memory、session/call、图片/音频结果、用户级控制与任务结果逐项绑定可信 principal；区分用户面与现有管理面。
- 固化显式 local-dev 单用户身份与云部署验证入口，禁止生产静默使用 guest 或可伪造 Header。
- LLM 真实失败返回明确 degraded/error，禁止把用户原文标作 model 回答后播报、记忆或加入有效回答历史。
- 修复 URL 空前缀与结构校验、Presence mouth 契约；此处只改后端校验，不开发前端。
- 完成最小威胁模型并冻结两个安全主题：身份/受控副作用，以及 Prompt Injection 的上下文信任与行为限制。Rust 具体边界在第八批完成 ADR 与集成。

### 主要交付物

- 安全写入契约、认证与资源所有权矩阵、威胁模型及迁移说明。
- 实际后端写入载荷 spy 测试、越权负例、降级/URL/Presence Contract 回归。
- 正常路径兼容策略、受保护入口清单与风险登记。

### 完成标准

- 正常批准事实可写入，原文中的测试 Secret 不进入持久化请求、日志或后台重试载荷。
- 跨用户读取、写入、打断、清理与结果下载在执行前被拒绝；正常同用户访问仍成立。
- 真实 Provider 失败不再返回“用户原文即模型回答”的假成功。
- 以上均由新增负向测试和原 Contract 回归证明，不以本规划文档代替证明。

### 本批不做

- 不建设注册、登录、账户 UI 或新的身份平台，不自研密码学。
- 不将所有安全候选同时立项；原性能主线移至第六批采基线、第九批完成量化收敛，不取消。
- 不把完整媒体隔离和通用安全网关加入本批。

## 第 6 批：操作生命周期、原子准入与提交一致性

### 目标

在现有 Redis/本地模式上建立最小操作契约，确保并发、重试、取消、删除和迟到结果不能改变不属于它们的当前状态。

### 主要工作

- 复用 event/session/turn/request 标识，补充稳定 operation ID、载荷摘要、generation、fence、deadline 和最小策略/人格快照。
- 将资源所有权、幂等占位、回合准入、代际推进组合为原子边界；本地与 Redis 共享同一状态机语义。
- 同键同载荷查询或复用原状态；同键异载荷冲突；超时且外部执行结果未知时标记 unknown，不自动重发。
- 打断、结束、新回合按作用域撤销提交资格；Memory 清空/禁用引入共享撤销版本，防止旧后台任务回写。
- 在聊天状态、checkpoint、可见 Memory、输出注册、TTS/播放与动作投递点落实资格校验；不能只在 API 或 Graph 入口检查。
- 对跨 Redis 与 Mem0 等非事务后端明确逻辑版本隔离和补偿边界；不以先检查后写声称全局原子或 exactly-once。
- 定义整轮剩余时间、重试与调用预算，并覆盖 State/Planner/LLM/Memory policy/Vision/ASR/TTS 及摘要隐藏调用。
- 在行为变化前采集可复现性能/调用数基线，第九批用同环境同负载对照收口。

### 主要交付物

- 操作契约、状态转换、原子提交与幂等保留期说明。
- 本地/Redis Contract、真实 Redis 双进程竞争、旧 fence、取消与删除屏障测试。
- 总 deadline/重试预算表、性能采集入口和迁移/回滚说明。

### 完成标准

- 测试保留期内并发同键仅一次受控准入，同键异载荷明确冲突。
- 取消/删除完成后，旧操作不能推进当前可见状态；已外发或已播放内容明确不可撤回。
- Redis 不可用时不悄悄切换本地真相，过期锁持有者不能以旧 fence 提交。
- 实际 Provider 调用数与等待时间受预算约束；线程超时不被误称为线程已停止。

### 本批不做

- 不重建 Redis/checkpointer，不引入 Kafka、完整事件溯源或新的工作流平台。
- 不承诺外部供应方全局 exactly-once，不无限保存 Prompt 或幂等记录。

## 第 7 批：后端输出交付与受控主动性

### 目标

在不开发前端、不强制更换传输的条件下，区分生成、交付和消费，用模拟消费者证明分段可关联、可恢复、可取消；主动开场不抢占用户。

### 主要工作

- 增加强类型分段，统一 operation/output/segment/event 关联、序号、版本和 text/audio/timing 状态。
- 复用 TTSDispatcher、本机播放器和 ResponsePacket；用兼容聚合器保留原平行数组，新增字段采用显式协议版本。
- 提供最小状态/分段查询、游标快照与幂等消费回执；传输 ACK、audio_ready、playback_started 和 playback_finished 分开。
- 有界排队、重复抑制、缺段超时及背压；用户打断或旧 generation 的回执不得推进当前状态。
- 会话级隔离 Speaking/Streaming/Interrupt 与 persona；本机物理音频设备另设显式互斥仲裁，不宣称设备可多用户同时独占。
- Presence 使用服务端冷却时钟、共享原子准入、用户开关、用户回合优先、过期丢弃与事件合并。
- 为现有 Vision 输出附最小观察信封：来源、时间、TTL、置信度语义、允许用途与操作归属；模拟输入，不启动摄像头或截图。

### 主要交付物

- 输出/回执/快照与观察事件 schema、兼容矩阵和模拟消费者。
- 乱序、重复、缺段、背压、断线恢复、跨用户 ACK 与 Presence 并发 Contract。
- 非前端的协议示例和故障恢复说明。

### 完成标准

- 生成完成不再自动等同实际播放；重复、越权与旧回合回执不造成错误状态转换。
- 模拟消费者在保留窗口内恢复不串段、不重复消费；超出窗口明确要求重新获取快照。
- 同会话并发 open 最多一次开场，关闭后零触发，客户端时间不能绕过冷却。
- 原聚合聊天接口仍兼容；本批不声称已经验证远端用户真实听感。

### 本批不做

- 不做 Flutter/Qt/Web，不开发新播放器、持续摄像头感知或自主 Agent。
- 不要求 token 流式生成、新 WebSocket 基础设施或复杂动作编排。

## 第 8 批：Prompt Injection 防护与 Rust 上下文审查

### 目标

交付一个窄范围 Rust 上下文审查组件，缓解不可信内容被提升为指令或写入授权的风险；最终权限与提交控制仍在 Python 执行点。目标不是承诺检测或消除所有语义注入。

### 主要工作

- 第五批威胁模型具体化：RAG、Memory、摘要、OCR/Vision、用户消息和模型规划字段按来源与用途分级，外部正文不得声明更高角色或授权。
- 使用版本化 ContextBlock/GuardDecision，绑定主体作用域、操作、内容摘要、允许用途、有效期与 policy version；可信字段由服务端装配，不从自然语言中提取授权。
- Rust 采用有界 CLI/stdio，负责严格协议解析、确定性用途约束、大小/深度/数量限制与可解释风险信号；固定策略不能被正文覆盖。
- Python 消费裁决，复查摘要与当前资格；拒绝/隔离内容不得进入任何相关 Provider 的有效指令或 Memory 写入路径。
- 主聊天、State、Planner、摘要、Memory policy 和 Vision 的模型输出一律为提案，不因通过 schema 就变成可信授权。
- 组件不可用时阻断依赖它的不可信上下文注入或受控写入；可选知识可显式省略后降级，不静默放行原文。
- 建立独立攻击/正常对照集、Rust 单测/边界与 fuzz、Python 集成 Contract、真实 Provider 独立攻击评测。
- 在 ADR 中比较外部报告建议的媒体解析隔离；本版不同时做第二个 Rust 媒体 worker 或通用网关。

### 主要交付物

- Prompt Injection 威胁模型补充、Rust 边界 ADR、版本化协议与有限策略表。
- 单个 Rust crate、Cargo.lock、Python 适配器、跨语言正反测试与构建指令。
- 攻击/正常样例、真实模型单独报告、误报/漏报与行为阻断证据。
- 降级、故障隔离、部署与回滚说明；不使用无审计依据的“注入安全率”。

### 完成标准

- 集成测试证明不可信材料无法修改主体、权限、策略或操作代际，未批准载荷不产生受控副作用。
- 风险识别指标与实际行为阻断指标分开，误报用正常对照集报告；Mock 不证明语义防护成功。
- panic、超时、超量输出、协议错误与缺失二进制均不会静默旁路；支持 Windows 本地与 Linux 部署的约定行为。
- Rust 必须实际接入，不以独立 demo 或 Python 重复实现冒充完成。若不可行，应提交范围变更审阅，不能沿用旧版“不采用也自动完成”的宽松条件。

### 本批不做

- 不做通用安全大脑、联网安全微服务、全部媒体解析器或模型分类器训练。
- 不把关键词命中、分隔符、SystemMessage 包装或 Rust 内存安全当作完整注入防护。
- 不允许模型输出自行授权文件、网络、播放、角色切换或长期记忆写入。

## 第 9 批：故障恢复、数据生命周期与性能成本收敛

### 目标

在第六批操作契约和预算上，完成真实故障恢复、数据清理与同条件性能对照，不再重复设计幂等/取消系统。

### 主要工作

- 复用 CloudTaskQueue 的 attempts、dead-letter、stale recovery；补齐 claim/租约、幂等占位到入队的原子性与作用域，不引入第二队列。
- 把已有 Memory 后台线程任务按第五批批准载荷接入可恢复任务路径；禁止将进程内 pending 当作持久完成，按真实业务结果记成功/失败。
- 验证 Redis 断连、Worker 崩溃、响应丢失、对象存储 5xx、Provider 401/429/503、重复投递及退避中取消。
- 完善单条/分层删除、派生摘要、输出对象、操作记录、死信和缓存 TTL；恢复备份后仍尊重删除/撤销版本。
- 复用 readiness/liveness 与既有失败策略，不为可选模型故障制造重启风暴。
- 以第六批基线为起点，记录冷启动/稳态/并发 P50/P95、排队、失败/降级率、调用数、可获 Token、音频时长、CPU/RSS 与预算耗尽。
- 同环境、同模型、同负载比较至少一项实测热点优化；缓存必须按主体/人格/数据版本隔离并可失效，质量指标不能退化。
- 无法获得真实 Token/价格时记录 unavailable，不用字符串长度伪装账单；单纯 Mock 延迟改善不充当生产收益。

### 主要交付物

- 依赖故障矩阵、恢复 runbook、数据保留/删除与备份边界表。
- 本地与真实 Redis/Worker 故障证据、恢复与取消/删除交叉测试。
- 同条件性能成本报告、容量假设与一项优化对照，或有数据支撑且经审阅的不优化结论。

### 完成标准

- 重启/重放不会复活已撤销操作、已删除记忆或过期输出，未知外部结果不盲目重试。
- 操作、task、call、对象、日志与备份均有保留期、责任人与测试或明确的验证边界。
- 共享状态故障不静默分叉，可选依赖故障有界；readiness 与 liveness 行为符合约定。
- 性能与成本结论可复现，并附第四批质量回归；没有测量证据不宣称优化收益。

### 本批不做

- 不新建调度平台、数据库或全量基准实验室，不扩大到前端压测。
- 不将受控重放描述为全局 exactly-once；不无限重试或靠无限保留保证恢复。

## 四、批次依赖关系

批次默认按以下顺序执行：

```text
第 1 批 基线与范围
  -> 第 2 批 多 Worker 状态一致性
  -> 第 3 批 CI/依赖/容器地基
  -> 第 4 批 Agent 质量
  -> 第 5 批 安全落库/可信身份/显式降级
  -> 第 6 批 操作生命周期/原子准入/幂等/取消/预算
  -> 第 7 批 输出交付/回执/观察/受控 Presence
  -> 第 8 批 Prompt Injection/Rust 上下文审查
  -> 第 9 批 故障恢复/数据生命周期/性能成本收敛
  -> 第 10 批 发布收尾
```

允许的调整：

- 第四批由用户自行实施期间，可以提前审阅第五批威胁模型、所有权矩阵和测试设计；第五批验收必须补齐第四批相关回归证据。
- 性能采集从第六批开始，第九批完成对照；安全样例从第五批开始收集，第八批完成跨语言集成。
- 第七批只做后端协议与模拟闭环，不等待前端；第九批复用第二、六批共享状态，不另建一致性系统。

不允许的调整：

- 第 2 批不得被删除或推迟到第 10 批。
- 第 3 批未完成前，不把后续评测和安全测试视为稳定门禁。
- 第五批已知风险不能全部推迟到第八批，Rust 不能替代身份验证与最终提交控制。
- 第七批不得在第六批提交资格未生效前扩大并发输出与主动行为。
- 第八批不得同时铺开 Prompt Injection Rust 组件、媒体隔离 worker 与通用安全网关。
- 第 10 批不得接收新的功能性需求。

## 五、V1.2 整体完成定义

V1.2 后端版本完成时，应同时满足：

- 多 Worker 下会话、LLM 线程、persona、Memory 清理和 Realtime 状态不会静默分叉。
- 存在合并必过的 CI 门禁、依赖唯一真源、锁文件和非 root 生产镜像。
- RAG、Memory、Vision、Persona/主聊天有版本化评测和失败回归。
- 关键 Runtime/Graph 路径有性能、成本和容量基线，并完成有证据的优化决策。
- V1.2 安全目标已经从威胁模型中选定并完成有限落地。
- Rust 上下文审查组件按第八批目标实际集成，具备稳定 Contract、资源上限和故障边界；不采用或移除必须先经过版本范围变更审阅。
- Cloud/Worker 故障恢复、幂等、重试、死信和数据生命周期经过验证。
- 发布产物通过依赖、Secret、配置、镜像、测试、评测和文档检查。
- 已知风险有负责人、优先级、缓解措施和截止时间。
- Flutter、Qt、Web UI 和其它前端工作仍不属于本版本完成条件。
- 第四批必须实际落地并验证，交付 MD 或参考答案回放不能算质量门禁完成。
- 批准的 Memory 载荷才可落库；身份、代际与撤销状态在真实执行点生效。
- 生成、投递与消费状态可分别查询，模拟消费者验证恢复，不能声称已验证真实远端播放。
- Prompt Injection 的结构/行为控制与语义攻击结果分别报告，不承诺通用防注入。
- 媒体解析仍在进程内等未选风险要显式处理或限定部署暴露；不可接受的高风险不能仅靠登记获得发布豁免。
