## 3. 当前镜像为什么大

当前 requirements.txt 中包含 Linux Torch 的 CUDA 依赖，例如 nvidia-cublas、nvidia-cudnn-cu13、nvidia-nccl-cu13、cuda-toolkit、triton。

大致依赖关系如下：

~~~text
sentence-transformers
  -> torch（当前 Linux 默认制品）
       -> CUDA / cuDNN / NCCL / Triton 等运行依赖
~~~

仅使用远程 LLM 并不会让包管理器自动知道服务端不需要 GPU。包管理器遵循声明、锁文件和平台条件选择制品。

当前工程还存在以下导入关系：

- aiagent/knowledge/vector_store.py 在模块层导入 HuggingFaceEmbeddings。
- apps/core/bootstrap.py 在模块层导入 FasterWhisperClient、录音与播放相关类。
- aiagent/vision/character_retriever.py 支持延迟加载 SentenceTransformer。
- CPU 版的 FAISS、图像处理、音频与可选本地能力仍可能被实际引用。

因此，本批选择“同版本 CPU-only Torch + 去除 NVIDIA 分发依赖”，保留当前兼容的 CPU 库。完全移除 Torch、Transformers、faster-whisper、pygame 等需要进一步拆分可选依赖和延迟导入，不能直接删包后假定主链路仍正常。这项更大的裁剪不并入第三批收尾。

已只读确认 PyTorch 官方 CPU 索引存在 torch 2.14.1+cpu 的 Python 3.12 Linux x86_64 wheel，未下载 wheel、未安装、未执行兼容测试。来源：https://download.pytorch.org/whl/cpu/torch/ 。

## 4. 基础知识

### 4.1 镜像体积、容器内存与显存

| 名称 | 含义 | 如何观察 |
| --- | --- | --- |
| 镜像体积 | 镜像只读层中的文件体积，占用磁盘和传输带宽 | docker image inspect、docker image ls |
| Docker 实际磁盘占用 | 镜像层、共享层、构建缓存、卷等的实际占用 | docker system df |
| 容器内存 | 进程、模型、缓存等的运行时内存 | docker stats |
| 显存 | GPU 执行使用的设备内存 | GPU 监控工具 |

移除 CUDA 包主要减少镜像体积、拉取流量和构建开销。是否减少实际常驻内存，取决于原来加载了哪些库和模型，需要在相同请求、Worker 数和运行条件下测量。

API 和 Worker 可以共享镜像层。不能简单把两个镜像显示的 SIZE 相加就当作实际磁盘占用；构建缓存也不等于正在运行的容器内存。本方案不要求清理旧镜像、数据卷或执行 docker system prune。

### 4.2 声明、锁文件和已安装环境

- pyproject.toml 表达直接依赖、版本约束和来源选择。
- uv.lock 记录一个可审阅的解析结果，不应手工编辑版本或哈希。
- uv lock --check 检查声明与锁文件是否同步。
- uv pip check 检查当前安装环境中的依赖约束。
- check_dependency_runtime.py 补充检查项目直接依赖是否实际存在。
- requirements.txt 是导出产物，不再单独维护版本；requirements-cloud.txt 保持一行 -r requirements.txt。

CPU 源属于依赖解析的一部分，必须先改声明、重新锁定，再构建镜像。不要在 Dockerfile 中先装 GPU Torch，再卸载 CUDA 包或覆盖 Torch；这会留下依赖不一致和额外镜像层。

### 4.3 CPU-only、禁用 GPU 与远程推理

torch.cuda.is_available() 返回 False，只能说明当前环境无法使用 CUDA，不能证明安装的是 CPU-only wheel。

有效检查应同时覆盖：

1. 安装环境中没有 NVIDIA、CUDA 工具链或 Triton 分发包。
2. torch.version.cuda 为 None。
3. 当前后端模块能够导入，主链路回归仍通过。

CUDA_VISIBLE_DEVICES 留空只能影响设备可见性，不会从镜像移除 CUDA 文件。

云端模型调用继续由原有 Provider 和 endpoint 配置决定。CPU-only 镜像不会自动修改 LLM、RAG、Memory、ASR、TTS 或 Vision 的 Provider；不要仅为了减小镜像把云配置换成 Mock。当前云模板的 RAG、Memory embedding、ASR 已有远程配置，视觉角色检索仍可能使用本地 CPU 模型。

### 4.4 多阶段构建

dependencies 阶段使用 uv 按锁文件生成 /app/.venv；runtime 阶段只复制该虚拟环境和白名单源码。

两个阶段使用相同的系统基础阶段，保证 Python 路径和动态库兼容。uv 二进制及其下载缓存不复制进最终镜像。多阶段构建不会让运行时必需的 CPU 库消失，体积收益主要来自 CPU 制品选择和不携带构建工具。

### 4.5 非 root 和权限

UID 10001 是本批部署约定，源码及其父目录应不可由服务用户写入，/app/data 应可写。

非 root 不等于整个根文件系统只读。本方案仍允许正常临时目录行为。既有命名卷或绑定目录可能保留旧 UID；镜像内 chown 不会自动修复一个已有宿主机目录的权限。

### 4.6 测试层次

| 层次 | 证明什么 | 不证明什么 |
| --- | --- | --- |
| 单元测试 | 确定性函数和局部策略符合约定 | 不证明容器和远程服务正常 |
| contrast 正反对照 | 每次破坏一个条件会触发对应失败 | 不等于 API Contract |
| API Contract | HTTP 字段、状态、错误结构兼容 | 不等于真实模型质量 |
| Mock smoke | 主链路可以组装和运行 | 不等于真实 Provider 表现 |
| 容器验收 | 真实镜像的 UID、权限、包和模块可加载 | 不证明真实依赖的业务行为 |
| 真实 Provider 验证 | 远程连接、模型、鉴权和真实响应 | 应单独记录成本、环境与结果 |

说明：

- 基础版本固定为当前锁文件使用的 2.14.1，避免为镜像精简顺带升级或降级 Torch 主版本。
- Python 版本规则中 ==2.14.1 可以匹配 2.14.1+cpu 这样的本地版本标识。
- Linux 从官方 CPU 索引解析 Torch；其他平台继续使用默认来源，不强制改变本地 Windows GPU 选择。
- explicit=true 将额外索引限制为显式指定的包，其他普通依赖仍由常规索引解析。
- 本轮核对的目标是 Linux x86_64、Python 3.12。其他架构仍需实际解析和构建验证。
- uv.lock 可能保留其他平台的记录；最终应按 Linux 容器内的实际安装结果判断，不能只搜索跨平台锁文件就宣称有或没有 CUDA。
- requirements 导出不保证完整保留 uv 的按包索引语义，因此新的 Dockerfile 直接使用 uv.lock 构建；使用传统 pip 安装 CPU 导出清单的外部流程需显式配置 CPU 索引和核验哈希。

~~~dockerfile
CMD ["sh", "-c", "exec uvicorn apps.api.http_server:app --host 0.0.0.0 --port 8000 --workers ${WEB_CONCURRENCY:-2} --proxy-headers --forwarded-allow-ips \"${API_TRUSTED_PROXIES:-127.0.0.1,::1}\""]
~~~

最终镜像不复制 requirements、pyproject、锁文件、测试、文档和脚本。锁文件仍是构建输入，可从 Git 提交追溯，不必放在运行镜像中。Python 从 /app/.venv/bin 运行，源码继续通过 /app 工作目录导入。

## 附录 D：scripts/check_container_runtime.py 完整替换代码

~~~python
import os
from importlib import import_module
from importlib.metadata import distributions


def check(uid, writable, exists):
    checks = {
        "uid": uid == 10001,
        "data_write": writable("/app/data"),
        "code_read_only": not any(
            writable(path)
            for path in (
                "/app", "/app/aiagent", "/app/apps",
                "/app/cloud", "/app/config", "/app/integrations",
            )
        ),
        "clean_image": not any(
            exists(path)
            for path in (
                "/app/.env", "/app/cloud.tencent.env", "/app/tests",
                "/app/docs", "/app/scripts", "/app/data/models",
            )
        ),
    }
    failures = [name for name, passed in checks.items() if not passed]
    if failures:
        raise RuntimeError("container checks failed: " + ", ".join(failures))


def check_cpu_dependencies(names, cuda_version):
    normalized = {name.lower().replace("_", "-") for name in names}
    forbidden = sorted(
        name for name in normalized
        if name.startswith(("nvidia-", "cuda-"))
        or name in {"triton", "pytorch-triton"}
    )
    if forbidden or cuda_version is not None:
        raise RuntimeError(
            "CPU-only policy failed: "
            f"packages={forbidden}, torch_cuda={cuda_version}"
        )


if __name__ == "__main__":
    check(os.getuid(), lambda path: os.access(path, os.W_OK), os.path.lexists)
    names = [dist.metadata.get("Name", "") for dist in distributions()]
    check_cpu_dependencies(names, None)
    torch = import_module("torch")
    check_cpu_dependencies(names, torch.version.cuda)
    for module in ("apps.core.bootstrap", "apps.api.http_server"):
        import_module(module)
    print(f"CPU-only Torch: {torch.__version__}")
    print("Container permissions and backend imports passed.")
~~~

此脚本不放入生产镜像，由已有 CI 通过标准输入执行。第一遍先检查安装包，防止 GPU 包已存在却因为机器没有 GPU 而被误认为正常；第二遍核对实际 Torch 的 CUDA 构建标志。

函数只在 __main__ 中读取真实环境。Windows 单元测试导入模块时不会调用 os.getuid，也不会导入 Torch。任何不符合约定的检查都显式抛出 RuntimeError，不依赖可能被 Python 优化模式关闭的 assert。

该 CPU 策略针对本批 NVIDIA/CUDA/Triton 目标，不宣称扫描了所有可能的 GPU 库或第三方包内嵌二进制。镜像体积和关键包状态仍应实测记录。

## 附录 E：tests/unit/test_container_runtime.py 完整替换代码

~~~python
from contextlib import nullcontext

import pytest

from scripts.check_container_runtime import check, check_cpu_dependencies


@pytest.mark.parametrize("uid,data,code,secret,error", [
    (10001, True, False, False, None),
    (0, True, False, False, "uid"),
    (10001, False, False, False, "data_write"),
    (10001, True, True, False, "code_read_only"),
    (10001, True, False, True, "clean_image"),
])
def test_container_policy_contrast(uid, data, code, secret, error):
    expected = nullcontext() if error is None else pytest.raises(RuntimeError, match=error)
    with expected:
        check(uid, lambda path: data if path == "/app/data" else code, lambda path: secret)


@pytest.mark.parametrize("names,cuda_version,passes", [
    (["torch", "numpy", "ctranslate2"], None, True),
    (["torch", "nvidia-cudnn-cu13"], None, False),
    (["torch", "CUDA_toolkit"], None, False),
    (["torch", "triton"], None, False),
    (["torch"], "13.0", False),
])
def test_cpu_dependencies_contrast(names, cuda_version, passes):
    expected = nullcontext() if passes else pytest.raises(RuntimeError, match="CPU-only")
    with expected:
~~~
