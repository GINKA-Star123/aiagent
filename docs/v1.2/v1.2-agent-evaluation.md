# V1.2 Agent 质量评测

## 入口与数据

统一入口：`python -m aiagent.knowledge.evaluation.agent_quality`。

版本化数据：`tests/fixtures/agent_eval/v1.json`。包含六份合成短文档、五条检索场景及十二条答案场景，覆盖 RAG、Memory、Vision、Persona、聊天；不替代原 RAG 120 条评测集。

## 离线门禁

```powershell
$env:PYTHONHASHSEED = "0"
uv run --locked --extra dev python -m aiagent.knowledge.evaluation.agent_quality --mode offline
```

执行真实 BM25、reranker、置信度与知识注入，并复用 Memory/Vision/Persona/聊天既有测试与新增整图测试。子进程 pytest 强制 Mock、关闭模型下载，不访问生产数据。离线答案规则率只统计 MainRunner 实际静态拒答，不代表真实 LLM 回答质量。

## 真实 Provider

先在本地配置已有 `LLM_PROVIDER`、Provider 对应的密钥/地址/模型，关闭 `ENABLE_MOCK_LLM`。不要把密钥写进命令、报告或提交。随后单独执行，不在 pytest 内运行：

```powershell
uv run --locked --extra dev python -m aiagent.knowledge.evaluation.agent_quality --mode provider --report-root data/cache/reports/agent_quality/provider --repeat 1
```

只调用 `invoke_messages_strict()`，不允许 Mock 或 fallback。使用生产 Prompt 构造组件、受控记忆/视觉观察与真实合成语料检索上下文；不运行完整生产 Agent，不调用真实视觉模型。默认十二次逻辑生成，`--repeat 3` 为三十六次；SDK 重试可能带来更多 HTTP 请求与费用。温度设置为零，不承诺固定 seed 或严格确定性。

默认报告只有规则结果、摘要和异常类型。`--include-answers` 显式保存模型答案，仅供本地排障，分享前再次检查内容；即使输入是合成数据也不能保证模型输出不含无关信息。

## 报告与退出码

每轮在报告根目录下创建 UTC 时间与随机编号组成的独立目录：

- `report.json`：模式、数据/人格/覆盖摘要、代码版本、评测器摘要、分域结果和指标。
- `failures.jsonl`：失败检查、失败/跳过用例、执行错误、基线退化；成功时为空文件。
- 离线额外输出各域 `.xml` 和 `.log`，可定位失败测试。

退出码：`0` 本轮门禁通过；`1` 质量或基线退化；`2` 配置、数据或执行错误。零用例、skip、非零 pytest 退出、缺失/损坏 XML 均不能当作成功。

## 基线管理

首次通过后人工查看报告与失败集，再选择对应 `report.json` 作为接受基线。通过 `--baseline 完整路径` 对比下一次结果。模式、fixture、人格、覆盖必须一致；Provider 还要求 Provider、模型、温度、repeat、timeout 相同。指标缺失或非法数值拒绝比较，默认不接受任何下降。

离线与 Provider 不互相比较；变更样本/规则后需要重新审阅基线。报告记录 Git HEAD，但不代表工作区无未提交改动；发布验收时另检查 `git status --short`，结合提交内容与评测器摘要确认来源。不要把失败报告、参考答案回放或 Mock 报告作为真实模型通过证据。

## 范围与限制

检索指标来自既有 RAG evaluator；答案指标是确定性词项规则通过率，不等同语义忠实度、事实正确率或人工满意度。Memory 删除测试验证 Runner 不保留旧上下文，真实后端删除/并发持久化需部署验证。Vision 使用合成文字观察，不证明图片识别和 OCR 精度。生产 FAISS/embedding 质量和完整真实多轮 Agent 尚未覆盖。报告中的逻辑生成数不是计费请求数。

## 第四批验收

新的评测器测试、Memory 整图与拒答测试通过；原单元/API/smoke 无退化；离线门禁无 skip 且报告完整；配置真实 Provider 后完成至少一轮并人工审阅全部失败结果。若真实 Provider 未跑或未通过，只能记录离线门禁完成，不能宣布真实生成质量验收完成。
