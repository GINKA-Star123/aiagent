# V1.2 范围与基线

## 一、本版本定位

V1.2 = Agent 质量、安全治理与后端工程化阶段。安全是其中一条主线，不是全部。
本版本不包含 Flutter、Qt、Web 控制台与其它前端分支。

## 二、基线与复现方式

完整机器可读报告由一条命令产出（产物在本地缓存目录，不入仓）：

```powershell
powershell -File scripts/test_v1_2_baseline.ps1
# 等价于：python scripts/v1_2_baseline.py --root . --output data/cache/reports/v1.2-baseline.json
```

报告结构：`schema_version / generated_at / repo / runtime / tracks（六类）/ defects / optimizations / summary`。

## 四、六类主线现状（摘要）

| 主线 | 现状要点 | 缺口 |
| --- | --- | --- |
| Agent 质量 | 329 个测试函数；RAG 有 32 条用例与阈值门禁 | Memory / Vision / Persona 无独立评测 fixture；缺答案级指标 |
| 性能与成本 | 阶段 `_latency_ms` 元数据齐备；有分阶段 timeout 配置 | 无基准脚本；无 Token/成本采集 |
| 执行状态 | 生产 2 Worker；LLM 线程仍为进程内检查点；指标为进程内 deque | 共享状态模块尚未落地（第 2 批） |
| Cloud 可靠性 | readiness 有 purpose 与脱敏；Redis 失败策略表 6 项；任务队列有 request_id / dead_letter / stale_recovery | — |
| 安全 | 日志脱敏、请求风险闸门、上传像素与魔数校验、CORS 风险检查、admin token 强度 | 见优化项；选定目标待第 6 批 |
| 数据与工程治理 | 配置一致性检查与仓库卫生检查已存在 | 无 CI；依赖三源并存；镜像 root |

## 五、已存在缺陷（与优化项分离）

| ID | 级别 | 批次 | 说明 |
| --- | --- | --- | --- |
| `multi_worker_thread_state_split` | P0 | 第 2 批 | 多 Worker 下 LLM 线程状态仍是进程内，短期记忆会断裂 |
| `no_ci_gate` | P0 | 第 3 批 | 没有任何 CI 流水线，测试与检查无法自动执行 |
| `metrics_process_local` | P1 | 第 2 批 | 指标为进程内 deque，多 Worker 下面板只看到部分流量 |
| `dependencies_unpinned` | P1 | 第 3 批 | requirements.txt 26 行全部未锁定，且与 pyproject / uv.lock 并存 |
| `pyproject_missing_web_deps` | P1 | 第 3 批 | pyproject.toml 未声明 fastapi/uvicorn |
| `image_runs_as_root` | P1 | 第 3 批 | 生产镜像以 root 运行 |
| `python_version_drift` | P2 | 第 3 批 | 本地 3.12.7 与镜像 python:3.11-slim 不一致 |
| `no_answer_level_metric` | P1 | 第 4 批 | 只有检索级指标，缺答案级判定 |

**前置批次：2 与 3。** 两者未完成前，后续评测与安全测试都不能算稳定门禁。

## 六、优化项（非缺陷，可延后）

- 第 4 批：Memory / Vision / Persona 评测 fixture；答案级指标
- 第 5 批：性能基准脚本；Token/成本采集
- 第 7 批：安全候选项（由第 6 批选题决定）
- 第 2 批：`instance_cache_hits` 中的进程内缓存（persona / 线程映射）评估是否共享

## 七、本版本非目标

- Flutter、Qt、Web 控制台与其它前端分支。
- 将 API / RAG / Memory / Runtime 整体重写为 Rust。
- 在威胁模型完成前预设必须开发某一种 Rust 安全工具。
- 新增第二套 RAG / Memory / 多 Agent 架构或缺少质量基线的新 Provider。
